= 為應用程式建立新排程
:allow-uri-read: 


[.api-doc-operation .api-doc-operation-post]#POST# [.api-doc-code-block]#`/accounts/{account_id}/k8s/v1/apps/{app_id}/schedules`#

指示要建立的 Schedule API 資源的所需值。



== 參數

[cols="5*"]
|===
| Name | 類型 | 在 | 必要 | 說明 


| account_id | 字串 | 路徑 | True  a| 
包含帳戶資源的 ID

* 範例：{{.Account}}




| app_id | 字串 | 路徑 | True  a| 
包含應用程式資源的 ID

|===


== 請求本文

指示要建立的 Schedule API 資源的所需值。

[cols="4*"]
|===
| Name | 類型 | 必要 | 說明 


| 類型 | 字串 | True  a| 
資源的媒體類型。定義的值為：

* "application/astra-schedule"




| 版本 | 字串 | True  a| 
資源版本。已定義值包括：

* "1.0"
* "1.1"
* "1.2"
* "1.3"




| 姓名 | 字串 | True  a| 
包含排程名稱的 JSON 字串。已定義的值包括：

* 最短長度：1
* 最大長度：63




| 已啟用 | 字串 | 錯誤  a| 
指示排程是否處於作用中狀態的 JSON 字串。定義的值為：

* 「true」- 排程處於作用中狀態
* 「 false 」 - 排程未啟動。如果未指定，則預設值為「 true 」。




| 精細度 | 字串 | True  a| 
指示排程精細度的 JSON 字串。已定義的值包括：

* 「每小時」
* 「daily」
* 「每週」
* 「每月」
* "自訂"




| 分鐘 | 字串 | 錯誤  a| 
包含數值的 JSON 字串，該數值指示要執行排程任務的分鐘數（0 - 59）。已定義的值包括：

* 定義的正規表示式為："^[0-9]|[1-5][0-9]$" 如果粒度設定為 "hourly"、"daily"、"weekly" 或 "monthly"，則此欄位存在。對於自訂排程，它將返回值 "0"。




| 小時 | 字串 | 錯誤  a| 
包含數值的 JSON 字串，該數值指示執行排程任務的小時數（0 - 23）。已定義的值包括：

* 定義的正規表示式為："^[0-9]|[1][0-9]|[2][0-3]$" 如果粒度設定為 "daily"、"weekly" 或 "monthly"，則存在此欄位。




| dayOfWeek | 字串 | 錯誤  a| 
包含數值的 JSON 字串，該數值指示要執行排程的星期幾（0-7）。已定義的值包括：

* 定義的正規表示式為："^[0-7]$" 僅當粒度設定為 "weekly" 時，此欄位才會出現。




| dayOfMonth | 字串 | 錯誤  a| 
包含數值的 JSON 字串，指示執行排程任務的日期（1-31）。已定義的值包括：

* 定義的正規表示式為："^[1-9]|[1-2][0-9]|[3][0-1]$"。僅當粒度設定為 "monthly" 時，此欄位才會出現。




| recurrenceRule | 字串 | 錯誤  a| 
包含 RFC-5545 第 3.8.5.3 節的 JSON 字串。重複規則。對於 DTSTART 參數,僅支援 UTC 時間戳記（以「Z」後綴表示）,且僅支援目前時間之前的時間戳記。對於 RECUR 規則部分,僅支援「FREQ」和「INTERVAL」兩種規則部分。對於 FREQ 規則部分,僅支援「MINUTELY」和「HOURLY」兩種值。僅當粒度設定為「custom」時,此欄位才會出現。



| snapshotRetention | 字串 | True  a| 
包含正數值的 JSON 字串，指示要保留的快照數量。零表示備份後應刪除快照。已定義的值包括：

* 最短長度：1
* 最大長度：63
* 定義的正規表示式為："^(0|([1-9][0-9]*))$"




| backupRetention | 字串 | True  a| 
包含正數值的 JSON 字串，指示要保留的備份數量。零表示不建立任何備份。已定義的值包括：

* 最短長度：1
* 最大長度：63
* 定義的正規表示式為："^(0|([1-9][0-9]*))$"




| bucketID | 字串 | 錯誤  a| 
JSON 字串，包含選用的儲存貯體 ID，指出建立時必須儲存備份的位置。如果未指定，將使用系統選取的儲存貯體。定義的值為：

* 符合 Astra 識別符架構




| 複寫 | 字串 | 錯誤  a| 
JSON 字串，指示排程是否為每個快照觸發 AppMirror 複寫。僅當應用程式定義了 AppMirror 關係時才生效。已定義的值包括：

* 「true」- 排程會觸發 AppMirror 複寫
* 「false」- 排程不會觸發 AppMirror 複寫。如果未指定，則預設值為「false」。




| 中繼資料 | link:#type_astra_metadata_update["type_astra_metadata_update"] | 錯誤  a| 
與資源相關聯的用戶端和服務指定中繼資料。定義的值為：

* 遵循 Astra Metadata Schema。如果在建立時未指定，則建立的元資料物件將不帶任何標籤。如果在更新時未指定，元資料物件的標籤、creationTimestamp 和 createdBy 將保持不變。


|===
.範例請求
[%collapsible]
====
[source, json, subs="+macros"]
----
{
  "type": "application/astra-schedule",
  "version": "1.3",
  "name": "Backup Schedule",
  "enabled": "true",
  "granularity": "monthly",
  "minute": "0",
  "hour": "0",
  "dayOfMonth": "1",
  "snapshotRetention": "12",
  "backupRetention": "12"
}
----
====

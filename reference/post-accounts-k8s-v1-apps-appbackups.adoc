= 為應用程式建立新的應用程式備份
:allow-uri-read: 
:imagesdir: ../media/


[.api-doc-operation .api-doc-operation-post]#POST# [.api-doc-code-block]#`/accounts/{account_id}/k8s/v1/apps/{app_id}/appBackups`#

指示要建立的 Application Backup API 資源的期望值。



[[parameters]]
== 參數

[cols="5*"]
|===
| Name | 類型 | 在 | 必要 | 說明 


| account_id | 字串 | 路徑 | True  a| 
包含帳戶資源的 ID

* 範例：{{.Account}}




| app_id | 字串 | 路徑 | True  a| 
包含應用程式資源的 ID

|===


[[request-body]]
== 請求本文

指示要建立的 Application Backup API 資源的期望值。

[cols="4*"]
|===
| Name | 類型 | 必要 | 說明 


| 類型 | 字串 | True  a| 
資源的媒體類型。定義的值為：

* "應用程式/astra-appBackup"




| 版本 | 字串 | True  a| 
資源版本。已定義值包括：

* "1.0"
* "1.1"
* "1.2"




| 姓名 | 字串 | 錯誤  a| 
包含使用者指定的備份名稱的 JSON 字串。如果未指定，或備份由排程啟動時，系統會為備份指派名稱。定義的值為：

* 最短長度：1
* 最大長度：63
* 符合 DNS 1123 Label Schema




| bucketID | 字串 | 錯誤  a| 
JSON 字串，包含選用的儲存貯體 ID，用於指示建立備份時備份檔案的儲存位置。如果未指定，則使用系統選擇的儲存貯體。如果沒有可用的儲存貯體，則在建立時將傳回錯誤。已定義的值包括：

* 符合 Astra 識別符架構




| snapshotID | 字串 | 錯誤  a| 
包含用於建立備份的快照的 JSON 字串。建立備份時，可以指定與被備份應用程式關聯的快照 ID。如果未指定，則會為備份建立一個新的快照。已定義的值包括：

* 符合 Astra 識別符架構




| 中繼資料 | link:#type_astra_metadata["type_astra_metadata"] | 錯誤  a| 
與資源相關聯的用戶端和服務指定中繼資料。定義的值為：

* 符合 Astra Metadata Schema。如果在建立時未指定、則會建立沒有標籤的中繼資料物件。


|===
.範例請求
[%collapsible]
====
[source, json, subs="+macros"]
----
{
  "type": "application/astra-appBackup",
  "version": "1.2",
  "name": "app-name-245"
}
----
====

== 回應

[source]

Status: 201, Returns the newly created appBackup resource in the JSON response body.
----
[cols="4*"]
|===
| Name | 類型 | 必要 | 說明 


| 類型 | 字串 | True  a| 
資源的媒體類型。定義的值為：

* "應用程式/astra-appBackup"




| 版本 | 字串 | True  a| 
資源版本。已定義值包括：

* "1.0"
* "1.1"
* "1.2"




| ID | 字串 | True  a| 
資源的全域唯一識別碼。定義的值為：

* 符合 UUIDv4 架構




| 姓名 | 字串 | True  a| 
包含使用者指定的備份名稱的 JSON 字串。如果未指定，或備份由排程啟動時，系統會為備份指派名稱。定義的值為：

* 最短長度：1
* 最大長度：63
* 符合 DNS 1123 Label Schema




| bucketID | 字串 | True  a| 
JSON 字串，包含選用的儲存貯體 ID，用於指示建立備份時備份檔案的儲存位置。如果未指定，則使用系統選擇的儲存貯體。如果沒有可用的儲存貯體，則在建立時將傳回錯誤。已定義的值包括：

* 符合 Astra 識別符架構




| snapshotID | 字串 | 錯誤  a| 
包含用於建立備份的快照的 JSON 字串。建立備份時，可以指定與被備份應用程式關聯的快照 ID。如果未指定，則會為備份建立一個新的快照。已定義的值包括：

* 符合 Astra 識別符架構




| scheduleID | 字串 | 錯誤  a| 
包含選用排程 ID 的 JSON 字串，用於指示備份是否由排程觸發以及觸發備份的排程是哪一個。僅在由排程啟動的備份中出現。已定義的值包括：

* 符合 Astra 識別符架構




| 狀態 | 字串 | True  a| 
包含指示備份運作狀態的值的 JSON 字串。已定義的值包括：

* 「pending」- 應用程式備份已排程進行探索
* 「正在發現」— 應用程式備份正在被發現過程中
* 「running」— 應用程式備份正在正常運行
* 「已完成」— 應用程式備份已成功完成
* 「失敗」— 應用程式備份處於永久失敗狀態
* 「已移除」- 應用程式備份目前無法存取
* 「未知」- 無法確定應用程式備份狀態
* 「deleting」- 應用程式備份已排程刪除




| stateUnready | 陣列［string］ | True  a| 
包含多個 JSON 字串的 JSON 陣列，每個字串指示應用程式備份無法轉換為「運行中」狀態、轉換為「失敗」或「已移除」狀態的原因。定義的值包括：

* 最短長度：1
* 最大長度：127




| stateDetails | 陣列[link:#type_astra_stateDetail["type_astra_stateDetail"]] | 錯誤  a| 
JSON 物件的 JSON 陣列，列出有關目前狀態的其他詳細資訊，包括達到目前狀態的原因。如果沒有可用的詳細資訊，此陣列將為空白。定義的值為：

* 最低項目數：0




| hookState | 字串 | 錯誤  a| 
JSON 字串，包含一個值，該值指示作為快照一部分執行的任何執行鉤子的狀態。已定義的值包括：

* 「failed」— 一個或多個執行掛鉤失敗
* 「success」- 存在零個或多個適用的 hook，且所有 hook 都成功




| hookStateDetails | 陣列[link:#type_astra_stateDetail["type_astra_stateDetail"]] | 錯誤  a| 
JSON 物件的 JSON 陣列，其中列出了有關「hookState」為何轉換為「failed」的其他詳細資訊。如果沒有詳細資訊，則此陣列為空白。

* 最少項目數：0




| backupCreationTimestamp | 字串 | 錯誤  a| 
包含時間戳記的 JSON 字串，指示備份時間。定義的值為：

* 符合 ISO-8601 日期時間架構




| totalBytes | 數字 | 錯誤  a| 
JSON 數字，包含備份中的總位元組數。



| bytesDone | 數字 | 錯誤  a| 
包含正在進行的備份已備份位元組數的 JSON 數字。備份完成後，該數字將與 totalBytes 欄位的值相符。



| percentDone | 數字 | 錯誤  a| 
包含正在進行的備份完成百分比的 JSON 數字。備份完成後，該值將設定為 "100"。



| 中繼資料 | link:#type_astra_metadata["type_astra_metadata"] | True  a| 
與資源相關聯的用戶端和服務指定中繼資料。定義的值為：

* 符合 Astra Metadata Schema。如果在建立時未指定、則會建立沒有標籤的中繼資料物件。
